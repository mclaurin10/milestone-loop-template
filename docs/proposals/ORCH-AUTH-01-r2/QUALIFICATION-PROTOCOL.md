# Advisory qualification protocol

The proposed authority owns completeness, freshness, isolation and claim boundaries. This document proposes implementation, subject to conformance review.

## Distinct purposes

Candidate-support declares affected cases, the actual controller platform, source/fixture identity and provider. It runs those supporting cases without automatically dispatching the complete Windows/Linux matrix. Its result is completion-ineligible.

Full-source-qualification belongs to one fresh literal no-argument source pnpm verify invocation. It executes all required outcomes/variants on both native platforms. Missing, stale or unsupported evidence keeps that gate non-passing. A purpose or CLI flag cannot promote supporting evidence or bypass integration rules.

The trusted outer control plane selects the declared purpose and dispatch set. A candidate cannot provide coordinator approval, choose a weaker contract or attest its own provider. Both purposes retain fresh execution identity, actual artifacts and producer-owned receipts.

## Producers, contained consumers and outer verification

Controllers needing Docker control run on authorized disposable hosts without unrelated projects or user secrets. Candidate children retain the real attested OCI policy with no Docker socket or credentials. WSL is Linux evidence only.

For a candidate check needing an outside producer, dispatch only the declared supporting cases on the required qualified host. If it can run inside the existing policy, no remote dispatch is needed. Missing required routing remains NOT_READY; no privileged nested container or workstation fallback is allowed.

For full qualification, execute the complete repeated builds, workflows and negative variants, adopter proofs, parity, containment and bounds. Fixtures execute their own scoped contracts without recursively asking for source readiness.

A bounded, typed, read-only input envelope binds purpose, coverage, exact source/authority/fixture, actual native platform/provider, fresh run/nonce and path/size/hash inventory. The outer controller obtains producer/job identity independently and pins the envelope digest. Reject links, traversal, changed files, exceeded limits, forged approval and candidate self-attestation.

The child validates real observations and receipts and writes an owned receipt for its inspection and declared coverage. The outer verifier independently repeats binding and completeness checks. Full readiness accepts only complete full-purpose observations; supporting evidence or a matching source hash is insufficient.

## Cost and feasibility

Record producers, purpose, selected cases, platform, command count and justification before dispatch. Several stages may inspect one immutable producer report within a fresh invocation without relaunching that producer. Distinct required builds/fault attempts still execute; candidate receipts and older same-commit evidence cannot be reused as fresh closure.

Preserve the five protected CI jobs and current bounds. Do not add an automatic per-commit full release trigger. This design makes no speedup claim. Record observed cost before expanding the next implementation slice.

First prove one real producer -> contained consumer -> independent outer audit and its correctly reached rejection, then native Windows feasibility early. Required regressions include cross-purpose substitution, forged provider/coordinator identity, stale nonce, changed source/fixture, omitted cases/platforms, zero-exit missing receipt and modified read-only input. Every original sixteen-family variant remains required at full qualification.
