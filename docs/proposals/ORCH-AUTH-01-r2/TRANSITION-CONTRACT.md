# Authority transition safety contract

These are normative outcomes and trust boundaries. MIGRATION.md describes an advisory implementation sequence.

1. Only explicit human approval of the exact normative content digest authorizes this source authority epoch. Approval is validated at the maintainer/control-plane boundary; candidate-authored files, repository prose, a package-integrity hash and this proposal's audit cannot supply it.
2. Preserve the original four authority files, lock/baselines, calibration state, commissioning anchor, complete amendment ledger and prefix, active readiness marker/history, protected script/workflow identities, and existing canonical state/leases/intents. Original WP6 evidence retains its original interpretation.
3. Implement strict compatible readers while the old generation remains active. Unknown or mixed authority/scope/epoch/approval fails closed. Legacy downstream/bootstrap contracts remain executable with their original tests and meanings. There is no weaker profile or worker-selected contract.
4. Commit the exact approved new authority/lock/supporting snapshots inertly at a real Git ancestor before activation. The new approved lock pins the fixed epoch snapshot prefix and allowlisted root files. Matching working-tree bytes or fabricated future hashes cannot substitute for those Git objects.
5. A separately committed migration request binds the approved normative digest, current audited implementation identity, old/new anchors and hashes, exact output set, old ledger tip and new epoch. The invocation captures its real clean attached HEAD/tree; the snapshot is a strict ancestor. No descriptor supplies arbitrary manifest bytes, file paths, weaker requirements or its own approval.
6. Acquire the existing mutation lease, reject competing/pending operations and unresolved reconciliation, and stage a coherent generation before replacement. Persist/fsync an exclusive intent before any active mutation. Recheck lease, branch/HEAD/index, approved request, intent and exact prior/new file states at every boundary.
7. All authority, verifier, planner and state/mutation consumers refuse pending or mixed publication. Crash recovery accepts only the same recorded request and exact prior/new states. Foreign changes remain preserved and diagnosed. Concurrency and before/after publication faults must reach their actual boundaries in regression evidence.
8. Publish the complete authority/lock/config/commissioning/ledger generation together after focused integrity checks. Preserve and link the old commissioning/amendment history; never truncate it. Missing source stages remain NOT_READY. A migration receipt is not readiness evidence.
9. Migration performs no implicit commit/reset, readiness rollback, controller-state replacement or verifiedCommit adoption. Existing old-epoch state is fenced and requires fresh exact new-epoch verification and independent resumable reconciliation before adoption. A recorded absence may be initialized only by a later authorized normal operation.
10. Retain independent review, exact command-owned artifacts and actual Git/runtime observations. After committed activation, reversal requires another explicitly approved appended authority revision; ordinary code fixes use normal verified source control. Candidate checks, new-epoch qualification and this revision cannot retroactively close WP6e or authorize WP6f interpretation.

Concrete module names, proposal tooling, internal record layouts and sequencing refinements are implementation decisions only when they satisfy every requirement above and preserve the normative public contracts. The approved file allowlist and claim/trust boundaries cannot be relaxed through implementation notes.
