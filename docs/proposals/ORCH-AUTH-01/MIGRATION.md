# Proposed authority and commissioned-baseline migration

Status: exact design for review; no approval or activation has occurred. This is ORCH-AUTH-01, a separate work package from WP6e/WP6f. The approval payload is the content digest in `review-manifest.json`; changing any proposed normative byte requires a new digest and review.

## Why a new epoch is required

At inspected commit `e590e38c32de2b5baa7423f66bbd8a0230b61839`, source commissioning uses authority base `0f4ab3e5ef39bda07d6e77356ad53fca9136cdd5`. The schedule anchor is `345591818b220964618dc4e80cce3c0e0213783c`. The active WP6e ledger is an append-only audit of the original v1 and owner-partition v2 schedules.

`authority-anchor.ts` requires the exact lock and all four active authority files to equal blobs at the commissioned strict-ancestor base. `contract-integrity.ts` additionally pins baseline IDs, thresholds and aggregation. `commissioning-audit.ts` and `source-schedule.ts` accept only the original source generation or its reviewed v2 transformation. `readiness-completion.ts`, verifier parsers and the aggregate assume the existing downstream stage registry. A new hash alone, moving the base ref, using CAL-1, rerunning one-shot commissioning, or using the WP6e schedule amendment cannot authorize this revision.

## Approval scope

Approval of this payload would authorize the exact four replacement authority files and proposed AGENTS/CONTRACT text, the new source-only acceptance/command/stage contract, the versioned lock design, legacy snapshots and exhaustive mapping, and the migration sequence below. It would authorize implementing and independently reviewing the supporting readers, validators, qualification workflows and migration tool in later bounded increments. It is not evidence that those implementations exist or pass.

Approval would not authorize changes to any original test's meaning, hidden-adopter authority, existing WP6e/WP6f plan/evidence/threshold/measurement identity, model policy, installed runtime dependencies, protected exact-runtime workflow, automatic integration, or acceptance claims. Proposed new source commands are additive; old placeholder script definitions can remain available as historical diagnostics but are explicitly absent from the new source schedule. Adopters retain their own script/profile contracts.

The agent must not create a record claiming human approval before the user supplies it. The future maintainer approval record stores the reviewed revision ID/digest, the user's exact approval reference, scope and date. A repository hash chain proves consistency, not the identity of an actor who can rewrite all history. Migration must validate that approval through the invoking maintainer/control-plane approval boundary; an arbitrary candidate-authored approval file is insufficient.

   Build and qualify the real source commands in isolated fixture repositories under the proposed authority; that is development evidence, not active-source readiness. Exercise mixed scopes, forged approval, wrong baseline, unknown fields, changed protected paths, missing files, and stale/foreign artifacts. Commissioned adopters without the new source discriminator continue through their unchanged legacy contract. Preserve all existing regression identities and add new ones to the existing ownership catalogue.

   The only new v2-anchor lookup prefix permitted for this revision is `evals/authority-epochs/orch-template.v1/root/`. Within it, file names come from the fixed authority/supplement allowlist. Do not permit arbitrary Git paths or trust current matching files as an anchor. Legacy anchors keep their original root-path lookup.

## Rollback and historical comparison

Before activation commits, use the same tool's recoverable abort/resume path, restoring recorded prior bytes only when paths still match expected prior/new bytes. After A is committed, do not delete the epoch/approval/migration ledger or readiness marker. A reversal is another explicitly approved, appended authority revision; preserve every intermediate identity and evidence. Ordinary source-code fixes can use normal cohesive Git reverts, but cannot silently reactivate an older authority epoch or claim its old PASS at the new HEAD.

Keep old verifier/authority/commissioning semantics executable in exact legacy fixture checkouts and the old WP6 evidence bound to its original commits. New source fixture tests must not silently reinterpret old BOT/SEED/METRIC assertions. The source-only dispatcher is added alongside the unchanged legacy registries; all consumers reject cross-scope evidence before evaluating status.
